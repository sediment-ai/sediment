# Factual evidence access and measured agent retrieval performance

The agent context flow loads and keyword-scores every permitted Session before choosing previews, then rescans the selected Session. Its retrieval credential cannot use existing exact inventory, manifest, or part reads. That prevents an external decision model from choosing authorized evidence independently of the keyword baseline.

Decision: Sediment establishes captured evidence identity, existence, source limits, and read authority. A consumer, such as JEV or a local equivalent, judges task usefulness. Preserve Git as the source of code evolution and preserve uncommitted Session evidence, including requirements and failed attempts. Model judgments never become Facts, access grants, Rewards, or training labels.

## T1: Reproducible baseline and comparison

Create a maintained Python benchmark for the public discovery-to-retrieval workflow using real PostgreSQL, fixed synthetic Facts, explicit authority, and native worker execution. Use existing dependencies and owned disposable resources. Include requirements and failed attempts with no commit observation, a known reference, exact large integers, and unrelated organization history. Compare unchanged keyword responses exactly across code revisions. Never call a synthetic chooser a decision-model evaluation or claim lower inference spend without measuring a model.

## T2: Grant-scoped factual reads

Add GET /query/context/evidence, GET /query/context/evidence/manifest, and POST /query/context/evidence/read as scoped siblings of the existing operator-only exact routes. Reuse EvidenceInventory, EvidenceManifest, EvidenceRead, EvidenceReadRequest, and FactStore projections. Requests name a Session; manifest also names a Fact ID; fetch names exact references. No keyword query or utility score is required. Both retrieval and operator authority remain restricted to the configured singleton/plural context grant on these routes. Authenticate and check membership before storage and repeat scope/disabled checks in the worker. The existing /query/evidence routes remain operator-only.

Retain existing exact-operation limits: 1,000 inventory calls, 32 distinct references, 64 KiB streamed fetch body, 8 MiB selected source columns, 1 MiB complete strict response. Do not truncate inventories, manifests, parts, or partial failures. Exact fetch preserves requested order and duplicate occurrences at distinct references. Exact reads may include reasoning; keyword exclusion is a selector rule, not an access rule. No raw payloads or Fact user identity are exposed. A known reference is not continuing authority; every request uses its own Quarantine-aware snapshot. Out-of-grant and unavailable cases remain content-free. Exact scalar values and original source identities survive all layers.

If optimizing worker setup, retain isolation, admission, cancellation, stdout bounds, and cleanup. Do not raise admission/source caps without a separately justified capacity decision.
